## 后续三个优先实现点

1. **实时演示平台边界**：将 `presentation.rs` 中 Mac 捕获与共用合成/输出窗口解耦，优先接已有 Windows 采集源，保持物理副屏和共享窗口两条路由；之后独立接 Linux X11/Wayland。需要实际目标机验证采集、显示输出、会议共享和性能。
2. **Linux 光标与输入路径**：梳理 X11 与 portal/PipeWire 帧的光标元数据、坐标和点击来源，补齐可用的形状/热点到既有工程及插值的通路；对确实无法获取的场景保留明确能力状态。Wayland 桌面环境和权限差异必须实测。
3. **移动采集逐平台接入**：先做 Android 的目标平台构建与 helper、server、ADB 查找/路径接线，再实现 Windows/Linux 设备启动与停止闭环；iOS 当前 helper 依赖 macOS 框架，应单列实际可实现方案。须目标机与设备验收。

Windows/Linux 录屏、截图、音频、摄像头、导出、权限、安装与回滚以及平台组合仍待逐项验证；上述顺序不关闭 U12–U16 或放宽任何既有门槛。此次未改仓库、运行编译/测试、操作桌面或设备，也未触发 CI。

主代理复核：移动setup非Mac拒绝与演示的非Mac分支已核对，U12a完成状态已计入。音频／摄像头的细分能力、非Mac静态壁纸后端和条件编译缺口仍须继续补齐；本矩阵为源码盘点，不关闭U12父项或目标平台验收。
