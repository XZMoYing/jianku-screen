# 界面设计与录前预设

日期：2026-10-16。应用版本：0.2.0-alpha.15。

## 硬性约束

所有应用界面使用统一的颜色、控件、形状与交互体系，包括继承的编辑器、截图编辑器、设置与辅助窗口。默认浅色，提供深色和跟随系统；旧安装首次迁移时将跟随系统改为浅色，已经明确选择深色的用户继续保持深色，以后选择跟随系统也不会被重复覆盖。

**禁止在界面左上角堆放大标题、副标题或无必要的 slogan。** 应用标识、当前工程名和用于操作的分组标签应保持紧凑。主要空间留给内容、预览与控制。

动画效果的研究目标保留；任何面向产品的文档、功能简介和界面文案不得使用“Screen Studio 同款”这类宣传表述。界面设计的调整不替换录制画面的运动求解、动态模糊和光标算法。

## 设计依据与差异

**启动主界面按本产品自己的录屏／演示流程设计，不参照 DogSC 的启动布局。** DogSC 仅作为界面交互运动和编辑器细节的参考；主界面的结构与现有编辑器统一，不复制另一个产品的启动页。

参考 [Material 3 的运动系统](https://m3.material.io/styles/motion/overview/how-it-works)、[文字层级](https://m3.material.io/styles/typography/applying-type)与 [Dog SC 固定版本](https://github.com/laogou717/dogsc/tree/167fde3ffb3c0ecb32c9b09c1777ec27b7243e07)的编辑器检查器、时间线分层和界面交互过渡。离线参考及哈希位于 `research/evidence/2026-10-16-expressive-ui/`。

默认从当前桌面壁纸提取种子色，生成主色、次色、容器、表面、文字和边线等整套颜色角色，移除固定蓝紫默认配色；沿用已经批准的品牌标识。卡片以色阶区分层次，弱化边线和装饰性阴影。使用较大的连续圆角与分段选择，不复制参考产品的布局细节或图形素材。

配色设置参考 Android 的“壁纸配色／基本配色”组织方式，提供最多四组壁纸候选、八组基本种子色、自选颜色、柔和／鲜明／灵动／淡雅／黑白风格及三档对比度。使用官方 [Material Color Utilities](https://github.com/material-foundation/material-color-utilities) 0.4.0 的 Celebi 量化、Score 候选排序和 Dynamic Scheme（2025 规范；库对不支持该规范的风格自行回退）；没有可用壁纸颜色时采用橄榄中性色备用，不采用库的默认蓝色回退。

取色时将壁纸缩采样到 96×96，处理后删除这一份临时取色图像；只持久化颜色和偏好，不上传壁纸。主窗口首次载入或重新获得焦点时检查取色，缓存一分钟以避免频繁捕获，设置里可立即重新取色。所有窗口监听同一配色设置，深浅切换重新生成对应角色；启动时读取已缓存的配色，减少闪色。改变界面配色不会改写已有工程的背景和其他媒体配置。新工程的基础背景改为砂岩色，保留其他背景供主动选择。

界面按钮采用有状态的解析弹簧：按住保持缩小，松开、移出、取消、窗口失焦和键盘抬起后回到原尺寸；快速反向时保留当前位移与速度。参考的按压响应为 0.26 秒／阻尼比 0.86，释放采用 0.30 秒临界阻尼。模式、来源和设置选项的共享选中标记使用 0.38 秒临界阻尼，响应参数按固有角频率 2π/response 转换，不把 response 当成固定动画时长。每个弹簧仅在运动未收敛时请求帧。

画面设置的选项标签固定，内容先用 120 ms 退出，再以 0.42 秒／阻尼比 0.86 的短距离进入；过渡可取消，快速切换只显示最后选择的内容。工作模式保留录屏、设备和演示组件实例，避免界面过渡重建会话。页面隐藏或减少动态效果时直接更新内容与选中状态，不等待不可见动画结束。以上是对公开界面运动参数的独立实现与适配，不是 SwiftUI 跨运行时逐帧等同的证明；原始媒体与 GPU 合成的运动参数保持独立。

路由入口统一加载 `expressive.css`，映射已有两套灰阶和编辑器语义颜色。Kobalte 弹窗、菜单、列表和选项卡及共用 Button/Toggle/Slider 同时接入，避免只修改主界面。

权限引导改为紧凑的功能列表，去掉原有营销内容。可以先进入工作台、设置和已有工程，准备录前画面；首次引导支持稍后设置权限。真正开始屏幕录制、截图和演示时仍由原生端重新检查系统权限，缺少时打开引导并明确报错。截图需要屏幕权限，带光标跟踪的录屏与演示还需要辅助功能权限；摄像头和麦克风沿用各自权限检查。进入工作台不代表已经获得录制权限。

项目目录中原有的 `jianku-screen-ui-redesign/` 草稿保留，不将其中的网页或移动端草稿视为当前应用已经实现的功能。

## 录前预设与保存

工作台始终提供画面设置：背景/图片/当前壁纸/动态背景、画面比例、留白、圆角、内边距、阴影及高级阴影、外框、细边框、光标大小和移动风格、倾斜、动态模糊、闲置隐藏、点击波纹、摄像头与声音，以及录制后自动运镜和默认倍率。可应用原有编辑器保存的完整预设。

设置存储与各工程的配置分开。开始录屏、截图或设备录制时生成 `capture-style.json` 快照；壁纸及背景图像复制到工程资产目录。结束录制后保留画面参数，再生成相应时间线。截图不显示电脑摄像头或光标；手机录制不虚构光标或电脑摄像头。已有 `project-config.json` 的工程和恢复流程不会被新默认值覆盖。

演示保持原有来源、质量、输出比例和焦点控制，并接入同一画面配置。开始演示时重新读取所选的当前壁纸。运行中的画面调整仍通过原来的串行更新通道传入合成器。

工作台显示的是标为“画面示意”的轻量示意图；真实摄像头、光标动态、动态背景的具体纹理与外框几何由既有 GPU 渲染器生成。时间线剪辑、字幕时间点、逐段运镜和遮罩位置需要有素材后才能编辑，不把空时间线当作录前画面参数复制进新工程。

## 当前壁纸

本机实查：系统采用航拍壁纸，`NSWorkspace.desktopImageURL` 却返回 `/System/Library/CoreServices/DefaultDesktop.heic`。此前一直读取该文件，导致界面显示旧背景。

macOS 先查找目标显示器实际的壁纸窗口图层，再通过公开的 Core Graphics 单窗口图像接口读取该图层；排除桌面图标和普通应用窗口，不通过隐藏窗口或截图整个桌面取得背景。新预览采用独立文件名防止 WebView 图像缓存复用。没有可读图层时才使用原来的文件路径方案；不读取或修改系统壁纸配置，不切换壁纸。

动态壁纸作为开始捕获时的静态快照保存在工程中；已有编辑器“当前壁纸”入口也使用同一路径。跨空间、外接显示器、不同壁纸来源与未来系统版本继续纳入交接验证。
