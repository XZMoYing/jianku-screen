## 产品目标与硬性要求

一款同时提供本地录制、完整编辑和实时演示的软件。录制模式保存独立画面、光标和音视频轨道，结束后进入编辑器；演示模式保持操作者主显示器不变，将合成结果输出到副显示器或可被会议软件选择的共享窗口。

**硬性要求：各种动画的目标是百分之百复刻 Screen Studio 的可观察行为与画面效果，但各种产品文档和功能简介不得使用“Screen Studio 同款”等竞品背书表述。** 研究资料可以标注参照来源。未通过统一输入的逐帧对照，不得宣称达到百分之百一致。

默认画面搭配优先采用 Cap 的背景、留白、圆角和阴影组合，再依据实际观感调整。画面预设与动画求解器分开，调整预设不能改变光标和镜头的时间行为。

动画与 3D 运镜优先继承 Cap 和已有参考研究。DogSC 主要提供有价值的小交互、编辑功能和壁纸获取思路，不采用其光标、点击、平滑和运镜曲线。低配置优化按成熟实现推进，不作为扩大开发范围或降低视觉效果的理由。

## 基础架构

- 核心：继承上游 Rust 录制、工程、编辑、音频、导出和 wgpu 渲染模块。
- 界面：第一阶段锁定已发布 0.6.0 的 Tauri 2 + Solid，实现完整功能基准。后续根据 GPUI 的实际功能覆盖、Windows 和多窗口输出验证决定是否迁移。
- 平台：保留上游 macOS 和 Windows 分支，共享画面布局、动画和合成规则；权限、捕获、设备和窗口输出由平台适配层处理。
- 实时输出：直接接入捕获帧与 GPU 合成，不以先编码视频再解码的方式绕行。视频帧队列有界，窗口和参数更新不阻塞界面。
- 规划：离线自动运镜可读取未来事件；实时规划仅使用已发生事件或明确的有限缓冲。连续移动、点击、拖拽和输入维持当前焦点，空闲退出；提供自动、手动、关闭以及手动切换快捷键。
- 输出：背景铺满输出区域，来源画面保持比例并置于可调画框；副屏断开时回到共享窗口。录制与演示可共用视觉参数，输出尺寸独立。

## 阶段与验收

### 第一阶段：备份与底座

1. 保存旧版全部已跟踪及未提交源码、研究、验证记录；提交、备份标签、远端备份分支和可独立恢复的 Git bundle。
2. 单独导入上游原始源码，核对目录 tree 与固定提交一致；记录授权、来源和后续修改。
3. 新应用使用独立标识、设置、日志、录制目录和协议；保留旧应用及用户原始工程。
4. 主窗口适当增大，确认不同缩放与工作区尺寸下可以使用。
5. 构建实际桌面应用；验证录制停止、保存、打开编辑器、重新打开工程、预览和实际导出。系统权限导致不能自动验收的项目明确记录。
6. 提交本阶段并打开应用供用户试用。

### 第二阶段：动画与画面

保留成熟编辑器和 3D 功能，按已有研究接入光标位置、倾斜、点击缩放、镜头构图与动态模糊处理链。使用同一输入、帧率和裁切的对照素材分别核对无模糊轨迹及最终合成；预览和导出读取相同动画结果。默认画面搭配单独验收。

### 第三阶段：实时演示

接入同一合成核心的实时来源、活动判定和原生输出窗口。验收连续操作不反复缩放、快速移动与点击一致、副屏连接与拔出、共享窗口、不同显示器比例、权限失败后的恢复及实际端到端延迟。虚拟显示驱动只有在共享窗口不能覆盖明确场景时再评估。

### 后续完整功能

以 Cap 已有编辑功能为基准，逐项补齐原功能台账中的差异；移植适合的小交互，增加移动设备录制、壁纸来源与动态背景、旧工程导入和 Windows 实测。移动设备的识别、连接、音频、旋转、丢失恢复和授权需要单独完成。
