# 移动设备录制

更新：2026-10-13，0.2.0-alpha.9。当前实施平台为 macOS。iPhone/iPad 与安卓都使用「录屏 → 手机与平板」入口，设备选择、声音、原生预览、录制状态、停止后保存和定位工程放在同一页面。

停止后先等待设备视频写入完成，再生成可编辑的 `.jks` 工程并自动打开编辑器。原始视频保留在工程的 `content/mobile/` 下，画面设置、镜头、3D 与动态模糊经现有 GPU 编辑/导出链路处理；设备画面不再经过普通视频导入的全片转码。设备自身没有输出触摸坐标时，不生成伪造的桌面鼠标事件；真实触摸跟随和设备外框另行推进。

## iPhone 与 iPad

使用系统 AVFoundation 和 CoreMediaIO 设备枚举，原生辅助程序由项目内 Swift 源码构建，与应用一起签名打包。接 USB 后需要解锁并信任这台 Mac；首次访问设备画面可能需要相机权限。预览保持来源比例，关闭预览窗口会结束并保存录制。

iPad 足够验证这条 iOS 捕获链路。当前捕获组件已编译，尚未用连接的 iPad 实测，不能仅因接口或编译通过宣称录制已完整可用。尤其需要检查设备音频、权限归属、横竖屏切换、动态分辨率、锁屏与中途断开。

AVFoundation 当前枚举逻辑不把所有 USB 摄像头当作手机；原生组件只选择 Apple 移动设备的复合媒体输入。参考依据为 [Apple AVCaptureDevice](https://developer.apple.com/documentation/avfoundation/avcapturedevice) 及 [OBS 原生捕获实现](https://github.com/obsproject/obs-studio/blob/master/plugins/mac-avcapture/OBSAVCapture.m)。API 使用顺序属于新实现，未复制其完整编辑器或动画实现。

## 安卓与 MI 6 兼容

复用本机安装的 scrcpy 4.1 和 adb，通过设备的原始编码流录制，保留设备生成的时间戳；这是 [scrcpy 官方录制路径](https://github.com/Genymobile/scrcpy/blob/master/doc/recording.md)，不用二次捕获投屏窗口。macOS 图形应用使用明确工具路径，避免依赖终端的 PATH；设备声音按 Android API 版本判断，Android 11 起具备系统声音捕获基础，应用仍可能禁止声音捕获。无声音的捕获仍可正常编辑。

设备由列表选择并用明确的 serial 参数定位，避免多个 USB/无线 transport 同时连接时选错。serial 只用于当前会话，不写入 `mobile-source.json` 或验证文档。录制过程只持有本应用启动的子进程；停止时发送 SIGINT 等待容器完成写入，超时保留原始文件并报告失败。辅助程序或设备断开后也尝试保存已收到的画面。

用户指定的 MI 6 使用定制系统和特殊连接流程。已只读核查 `mi6/scripts/scrcpy-usb.sh`、无线启动脚本及相关历史记录。有线启动器的关键点是明确选 USB（`-d`）；本项目用所选 USB 设备的明确标识实现等价选择。无线脚本的重连/预热有自己的前提，当前实现没有盲目执行网络重连、USB 配置修改或接管脚本。

MI 6 兼容分支只匹配 `product:sagit` 且 `device:sagit`。该分支执行有界的无副作用 shell 就绪检查，并在无预览录制时仍保留 scrcpy 控制通道所提供的默认唤醒行为。其他机型不启用此分支。按 USB 启动器方式已得到可解码的 1080×1920 视频；此结果不表示所有安卓机型已经验收。

本设备必须持续保持 VPN Hotspot 与 NekoBox 运行。测试和实现不得强停这些应用、重启手机、更改 VPN/热点/Wi-Fi 配置或重启 ADB 服务。已检查短录制前后这两个应用仍在运行；仅停止本次启动的电脑端录制进程。原始手机视频留在本机应用数据目录，不进入 Git，也不用于公开截图。

## 工程格式与剩余验收

从本版开始，新录屏、截图、设备工程、视频/图片导入与可携带副本统一用 `.jks` 文件包。历史 Next/Cap `.cap` 仍按原格式读取，不批量改动原文件。原 Qt `.jianku` 使用另一套时间线与元数据，暂未实施转换；打开时明确提示使用保留的旧版，不仅改后缀就宣称兼容。

原始项目、批准品牌图稿、工具依赖和本阶段证据分别在项目的 `assets/branding/`、`next/cap/` 与 `next/verification/2026-10-13-mobile-brand/`。后续待验证项集中在 [交接清单](待验证项目交接.md) 的 `V2-Mobile-01～04` 与 `V2-Project-03`；Windows 按用户明确指示推迟到迁移环境后处理。
