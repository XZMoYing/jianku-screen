# alpha.29：书签时间线与删除撤销

2026-10-25。用户明确将实机验收顺延；本轮只使用合成视频和自建工程验证，不要求连接手机、iPad、外接屏或会议软件。

## 功能与边界

- 编辑器增加书签标记行，弹窗与标记行共用源坐标映射。剪除的时刻保留在列表中，重复使用的素材显示多个位置；变速、重排、转场与全屏文字停留使用既有映射。
- 密集标记合并为入口，点击后选择具体书签；单个标记直接定位并暂停。标记不进入视频渲染和导出画面，不改写媒体。标记用于跳转，暂不支持拖动改写源位置。
- 书签面板提供“撤销上次删除”。当前工程会话最多保留最近 20 次成功删除，关闭编辑器后清空撤销记录；已经恢复的记录写入工程。这个按钮与画面编辑的快捷键撤销分开。
- 原子恢复只插回对应原始记录，保留其源时间、观察时间、名称和顺序，也保留其他书签后续的修改；标识冲突或保存失败会报错，不覆盖现有数据。保存失败不新增撤销项，恢复失败保留重试项。
- 书签数据读取失败时只显示面板错误，可“重新读取”，不阻断编辑器。资源按时间线内容刷新，不随播放头更新；等价时间线不重复查询已由前端模型测试覆盖。
- 多段来源的默认名称改为“片段 1、片段 2”，英文模式为 Clip 1、Clip 2；自定义名称保留。新增文案有中英文词条，CLI 及其他入口的全部本地化仍在队列中。

## 验证

- 前端 32 项：标记布局、边缘密集分组、恢复失败重试、重复操作互斥、读取失败恢复、相同时间线不重复查询，以及现有轨道/名称/语言回归。
- 原生书签 5 项：源映射、最终素材边界、原子保存、删除恢复及失败保持文件；原生绑定导出 1 项。桌面 TypeScript、相关 Rust 编译和改动格式检查通过。
- 打包 debug：四段剪辑、两个来源、2 倍速、重复使用与已剪除时刻，5 条书签投射为 4 个可见入口。单个标记跳到第 45 帧，分组选择跳到第 120 帧；编辑器计时末段显示帧数，资源为 60 fps。
- 同一应用内命名、删除、修改另一条名称、关闭/重开面板、撤销、连续两次删除/撤销，以及删除全部/恢复全部均通过。书签跳转后播放 1.5 秒收到 90 条画面传输消息；这是通道消息数，不是实际显示帧率基准。
- 冷启动重新打开后，5 条书签的名称和顺序保留，删除撤销栈清空。向本轮合成工程临时写入负时间的无效书签，页面显示错误而编辑器仍在；恢复原文件并点击“重新读取”后列表及标记恢复。完整工程和原始媒体未提交。

[editor.json](editor.json) 与 [recovery.json](recovery.json) 保存实际事件。[make-fixture.py](make-fixture.py) 可生成纯测试图案工程；两份 review 脚本通过既有 debug 检查入口点击实际控件。首次 UI 截图 [editor.png](editor.png) 只包含合成工程；随后仅补充了标记宽度/边缘碰撞算法，相关新增回归已通过，截图不作为最终优化包的像素对照。
