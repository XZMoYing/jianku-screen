# 3D 轨道拖动期间整窗加载占位检测（alpha.92）

安装版 0.2.0-alpha.92／2026.92.0。沿用历史闪烁取证方法：用 `CGWindowListCreateImage` 只采集被验证归属的编辑器窗口（非整屏），在真实鼠标拖动 3D 轨道片段期间连续取帧，分析是否存在整窗加载骨架占位或大面积闪变。

## 方法与夹具

- 夹具：自有合成工程 `拖动与缩放验收.jks`（3D 轨道两段 1–3 s、5–7 s）。
- 采集：`record-owned-window-cg`（新建同款工具，仅接受 `/private/tmp/jianku-flicker-20261108/` 输出路径与工程名前缀），窗口 1680×954，约 5 ms 间隔取帧；基线 3.5 s、拖动场景 8 s。
- 操作：采集开始后 0.5 s，用真实鼠标把第一段 3D 镜头由 (507,901) 拖到 (587,901)（16 步），保存后 Cmd+Z；结束读取工程配置，3D 段恢复 1–3／5–7。
- 分析：全窗口缩放到 96×54，逐帧统计 luma、浅灰/白/深色占比、与基线参考帧的像素变化比例、相邻帧平均差；以历史占位特征（大面积浅色/白、亮度突变）判定候选。

## 结果

- 基线：139 帧／3.46 s；luma 213.52–213.53；与参考帧变化比例 0；最大取帧间隔 29.9 ms。
- 拖动：316 帧／7.97 s；luma 204.9–213.5；拖动开始约 0.97 s 出现一次最大相邻帧差 15.99（预览开始响应 3D 姿态），随后与参考帧的变化比例稳定在约 12.3%（预览区域随 3D 移动而变化），浅灰占比最高 0.206（基线 0.184）。
- **未检出整窗加载占位候选帧（candidateRuns 为空）**：没有任何帧出现大面积白/浅灰占位或整窗亮度突变；变化集中在预览区域，面板布局稳定。
- 采集质量：writer 丢帧 0；拖动期间最大取帧间隔 59.6 ms（输入事件与采集调度的间隔，不是产品渲染帧率结论）。

## 边界与结论

- 本场景（移动 3D 镜头、8 秒窗口）在 alpha.92 未复现历史 alpha58 的「整窗 EditorSkeleton」4 段占位；alpha59 已修书签触发链。**不能据此关闭 U22c2b9b4 或宣称连续视频闪屏已修复**：短于取帧间隔的瞬态、启动/书签/快速切页/语言切换/快速反向等其他触发仍未覆盖，阈值检测也是启发式。
- 用户报告的「拖动频繁闪屏」仍需逐触发场景复现；本证据作为 alpha.92 拖动场景的负向结果与可复跑方法记录。
- 未读取用户真实工程；测试后工程 3D 段恢复原值、应用正常退出。
