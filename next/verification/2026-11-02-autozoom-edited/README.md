## 映射与规则

新的`generate_zoom_segments_for_timeline`从保留片段读取点击，减去各take媒体起点，按修剪范围、速度、重复／重排及转场后的当前时间映射，再叠加全屏文字停顿。使用与渲染一致的incoming光标：转场期间不把outgoing尾部点击重复计入。半开源范围让拆分边界归属后一片段。只读取被引用take的事件，保留take文件读取失败会报错，避免悄悄输出部分镜头。

Cap固定参考的点击区间函数逐字相同，见`generator-reference-check.json`：300毫秒预留、2500毫秒尾随和2500毫秒间隔合并等规则、默认倍率与动画曲线未改。该函数本来不消费移动事件；自动焦点／光标轨迹继续由渲染链路现有媒体映射处理，没有另拟移动轨迹。

初始录制完成时仍用原project生成入口；编辑器生成命令读取已保存的编辑配置。没有改命令参数或手改生成绑定。

## 异步边界

前端先flush当前工程，核对序列化快照，再请求生成。请求期间的编辑或Undo／Redo以revision和快照使旧结果失效；重复请求、owner移除后结果／提示都被抑制，正常生成只记一次可撤销编辑，不跨await暂停历史。空结果保留原有提示和轨道行为；补齐过期结果的中英文文案，空点击提示复用已有英文词条。

第二次链路复核发现预览和裁剪预览也会向同一个内存watch排队写配置。因此最终命令在blocking任务中只读前端刚flush的`project-config.json`，不从临时预览watch取timeline；使用直接serde读取以免触发加载迁移写回。原子保存契约沿用现有实现，读取／解析失败返回错误。该最终入口改动经过release check，具体旧预览交错的运行时场景仍需在新包验证。
