# 实时预览与动态壁纸性能验证（alpha.19）

## 复现条件

M1、16 GB、macOS 14.7.4；使用本机原有录前设置。背景实际指向 Apple 本机航拍视频 `5C987900-AD53-469C-8210-CABBCCDDFCAE.mov`，3840×2160、239.76 fps、10-bit SDR HEVC，关键帧约每 5 秒。系统素材未复制进仓库。首页输出仍为 960×600 RGBA；演示按原有输出设置测试。

alpha.17 的约 55 fps 数据来自渐变背景，不能推及本次视频壁纸。这里重新测量了可见的 alpha.18 窗口作为对照，原始计数见 [baseline.json](baseline.json)。首页 12 秒只显示 3 帧，最大间隔 8921 ms；演示 12 秒只产生 1 帧，最后一次处理耗时约 17435 ms。这与用户描述的几秒刷新一帧一致。

## 根因与修复

原壁纸通道把高帧率源中间的每帧依次解码、下载到 CPU，再同步做 RGBA 缩放、逐字节复制和 GPU 上传。处理滞后导致下一次追赶更多帧，拖住同一合成器。改为实时播放场景使用 AVPlayerItemVideoOutput 调度、VideoToolbox 解码与 IOSurface GPU 导入，复用现有 YUV 转换器；不逐帧追赶源视频。原生壁纸保留源分辨率，未降低输出分辨率、模糊采样或其他效果。10-bit SDR 仍允许实时通道，HDR 按 PQ/HLG 传递特性判定并保留原精确通道；有透明度或非 4:2:0 的源也不强制转换。

首页与演示选择收到帧即显示，避免 WebKit 不活跃窗口的动画回调暂停阻塞显示。编辑器的时间轴调度默认保持。首页示例与壁纸采用独立时钟，示例循环不再把壁纸每 6 秒重置。精确读取仅下载实际选中的硬件帧并批量拷贝，编辑器和导出仍按指定媒体时间采样。

## 复测方法

[playback-review.js](playback-review.js) 只在 debug 构建通过已有本地检查入口注入。先播放首页，随后测试演示单独运行、首页与演示同时运行、演示窗口隐藏。记录 WebSocket 收帧、显示线程回执和原生输出计数；不把原生计数单独当作窗口实际显示的证明。

[window-cadence.swift](window-cadence.swift) 只读取本产品可见的演示窗口，每约 100 ms 采样一次，保存图像哈希计数而非画面。它用于确认窗口像素持续变化，不用于声称显示器扫描频率；采样阶段的系统窗口抓图开销应与无抓图阶段分开读取。

另将实时通道的静止渐变合成帧与既有合成入口比较全部 RGBA 字节。这个对照验证合成及传输，不代表异步视频壁纸与精确时间采样逐字节相同。

## 打包应用复测结果

完整计数见 [after.json](after.json)，检查范围见 [verification.json](verification.json)。测试中的后台指原生窗口隐藏，并不等于已经验证会议软件捕获隐藏窗口。

| 场景 | 结果 | 帧间隔 |
| --- | --- | --- |
| 首页，视频壁纸，12 秒 | 720 帧，60 fps | P95 19 ms，最大 22 ms，无大于 50 ms 间隔 |
| 演示单独运行，1728×1080 | 原生 12 秒输出 645 帧，约 53.75 fps；无抓图的显示采样约 53.79 fps | 该显示采样 P95 23 ms，最大 56 ms |
| 首页与演示同时播放 | 首页约 44.38 fps；演示中间 5 秒采样约 35.79 fps | 首页最大 101 ms；演示最大 55 ms |
| 演示窗口隐藏 | 原生 6 秒继续输出 277 帧，约 46.17 fps；显示回执继续发生 | 隐藏阶段完整采样约 46.59 fps，最大 85 ms |
| 可见窗口像素抽查 | 3.03 秒，24 次采样得到 24 种哈希 | [window-pixels.json](window-pixels.json)，不保存画面 |
| 合成与传输对照 | 2,304,000 字节 RGBA 全部一致 | 只针对固定的渐变示例 |

启动演示到首帧就绪约 1.04 秒，首帧处理约 578 ms；并非零成本启动。首次输出显示采样含窗口像素抓图，约 53.39 fps、最大 160 ms，应与后续无抓图窗口分开看。原生与显示帧号偶有重复，不能将计数当作每帧画面都不同；另做像素抽查只证明可见窗口持续变化。

本轮解决了高帧率视频壁纸造成的秒级停顿；未宣称两个合成器同时播放时也恒定 60 fps。保持原有录前设置，未因测试改写用户的背景和动效参数。原生构建、4 项壁纸回归、3 项显示线程测试、12 帧解码/时间戳对照、TypeScript、格式和严格签名检查通过。
