# U06a：中文、本土化与语言切换静态台账

本轮完成静态工具与人工源码台账，未完成逐页运行验收，没有交付新的翻译安装包。应用仍为 alpha.45，U06/U07/U08父项保留；下一项是U07a编辑器显示调用修复。

## 覆盖及结果解释

scripts/jianku-localization-audit.mjs使用项目现有TypeScript解析器读取288份桌面TS/TSX源文件，登记2331处候选。其中1715处已能识别翻译调用或已核对的共享标签机制，614处需看调用链，2处词典待核。数字不是漏译数量，也不是完成率；614处中458处已经有词条，仍须检查显示时是否实际调用翻译。

两个待核词典项都是localize("Cap")，目前会走已有品牌回退，不直接判为漏译。词典共中文1514键/英文1653键，全表插值占位符没有发现键值不一致。保留实际字面量空白，避免把有词条的“ 秒”错误当缺词条；JSX文本才按HTML空白规则归一化。样式和脚本正文、测试、声明文件、生成绑定不计为待翻译界面文案。

另登记6处模块初始化时执行翻译的调用，需验证延迟加载和语言往返时会不会缓存旧语言；尚未把它们全判为运行缺陷。发现一个上游默认URL，仅登记来源及无查询参数的地址；动态URL、实际网络请求和入口拦截继续U10，不在本轮访问服务。

findings.json包含17条人工复核记录：11条确认存在未接翻译的显示调用，3条数据流/时机/可达性待核，3条已有机制或需保护的内容。涉及多选数量、裁剪提示、添加镜头、图轨导入、设备空态、恢复数量、自动化选择框和托盘最近项目。字幕模型选项等静态数据不能仅凭英文标签判漏译，需核对最终渲染。所有记录的runtimeVerified均为false，保留文件、行号和源码SHA。

page-ledger.json覆盖14个产品区域：首页、目标/设备、权限、录制/恢复、两个媒体库、编辑器、导出/字幕/错误、截图、演示、摄像头/移动设备、提词器、设置/自动化/集成、原生菜单、账户/许可。每个区域都仍需实际界面和语言切换验收。原生tray/windows/interface_language及系统菜单做了单独人工源码复核，前端解析器没有假装解析Rust。未覆盖的原生错误、服务端返回、实验GPUI独立工作区、用户自定义内容与目标平台实际显示继续审计。

## 使用与验证

在next/cap运行：

```sh
node scripts/jianku-localization-audit.mjs --output /absolute/new-report.json
```

输出必须是新文件，父目录需存在。已有报告会以EEXIST拒绝覆盖。工具只读产品源码和词典，不替换文案、不执行应用源码、不启动服务器。输出包含引用来源与保守分类，不是“零英语”检测器；技术格式、扩展名、快捷键、字体样张、用户数据和必要许可归属可能应保留。

完整报告压缩在inventory.json.gz，summary.json保留分组计数，解压前后SHA在摘要中。读取源文件逐个SHA均一致；两次运行报告逐字节一致，重复输出路径被拒绝且原报告SHA未改。实际源码案例核对了共享Show keyboard、条件设备空态、未包翻译的+ Add shot、带空白的秒词条和style/script排除。现有3项i18n回归通过，Node语法检查、脚本及JSON局部Biome通过，见validation.json。拒绝覆盖的预期错误记录在refusal.log，不是产品失败。

扫描成功退出不表示全部汉化完成；字典命中、静态数据和模块调用识别都不能代替实际渲染。没有修改生成绑定、录制工程或媒体，也未修改画面效果。完整候选版仍受导出稳定性、严格解码色度、UI/物理与Windows/Linux目标环境验收约束。
