# 编辑器交互首帧延迟采样（alpha.99，U26/U22 性能线索）

安装版 alpha.99。用自有编辑器窗口连续取帧（CGWindowListCreateImage，仅单窗口），在真实鼠标事件前记录时间戳，检测动作后首帧可见变化，测量点击→画面更新的延迟，并检查交互期间取帧间隔是否有主线程卡顿迹象。

## 方法

- 窗口 1680×953，~40fps 单窗口取帧 13s（writer 丢帧 0）；ui-drive 在事件投递前输出 eventStartUnix。
- 动作序列（间隔 1s）：素材与片段、字幕、返回编辑器、分割工具开/关、空格播放/暂停。
- 逐帧 96×54 平均差，动作时间后 0.8s 内首个 diff>0.08 的帧视为可见变化；同时统计交互窗口内取帧间隔。

## 结果

| 动作 | 首帧可见变化 | 备注 |
| --- | --- | --- |
| 打开字幕面板 | **4.1 ms**（diff 1.16） | 面板出现的大范围变化 |
| 返回编辑器 | **13.5 ms**（diff 36.89） | 大范围变化 |
| 分割工具开 | **136.3 ms**（diff 0.14） | 仅强调色小范围变化；两次点击后 AX 状态为关闭（切换生效） |
| 暂停 | 35.7 ms（diff 0.11） | |
| 播放 | 224.7 ms（diff 0.13） | 受静帧内容影响，不能当作播放启动延迟 |
| 素材与片段（首次） | 未检出可见变化 | 面板初始状态/坐标命中不确定，不作结论 |
| 分割工具关 | 未检出（diff < 阈值） | 颜色变化低于检测阈值，AX 状态已关闭 |

- 交互窗口内取帧最大间隔 **83ms**，>80ms 共 1 次，**无 >100ms**，本轮未观察到明显主线程阻塞。
- 局限：单次采样、阈值检测（小范围颜色变化可能漏检）、未使用真实工程；不据此关闭 U26/U22 性能项。
