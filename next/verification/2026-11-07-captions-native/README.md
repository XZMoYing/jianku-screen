# 字幕轨原生交互验收与保存重开问题（alpha.89）

安装版 0.2.0-alpha.89／2026.89.0。在自有合成工程上，用真实鼠标事件（CGEvent HID）操作时间线「字幕」轨：验证相邻字幕段的移动／裁剪／撤销，并核对保存重开后的持久化；由此确认一个真实缺陷：**字幕轨的计时编辑在重开工程后丢失**。

## 夹具与定位

- 复制自有合成工程（已含录音生成的 4 条字幕）为 `字幕轨验收.jks`，改写 `recording-meta.pretty_name`。
- 字幕轨头「选择轨道：字幕」在屏幕 y 754，lane 相对中心 y≈751；片段与两侧手柄可从 AX 读取。
- 4 条字幕初始：`0–1.79`、`2.09–4.92`、`4.92–6.51`、`7.37–8.0`（第 2、3 条首尾相接，第 2→3 相邻）。

## 缺陷结论与源码依据

- `captionSegments`（输出时间）是从 `captions.segments`（源时间母版）经 `synchronize_captions`／`derive_caption_track_segments` 投影出来的派生轨道；工程重开时会重新投影。
- 字幕轨拖动（`CaptionsTrack.tsx` 的 `createMouseDownDrag`）只写 `timeline.captionSegments`，没有回写 `captions.segments`，也没有把 `sourceTimed` 置为 false；编辑器里的投影 effect（`context.ts` 的 `deriveCaptionTrackSegments` + `reconcile`）会在重开时用母版重新覆盖。
- 因此用户在时间线上看到的字幕移动／裁剪是**临时的**：保存与关闭后文件里仍是编辑值，但重开工程即回退。这不是本轮操作问题，也不是邻接钳制；第 3 条在可动范围内确实移动成功。
- 第 2 条的「无法移动／右裁剪」是邻接边界钳制（第 3 条紧贴其 end），行为本身合理，不计缺陷。

## 修复方向（待实施，U25b1）

- 在字幕轨计时编辑结束时把输出时间反算回源时间并写回 `captions.segments`（含 words 起点重基），或明确提供「脱离源计时」动作后把 `sourceTimed` 置 false；两种方案都要加回归：移动／两端裁剪后保存重开仍保留，且不破坏字幕文本、words 与既有 override。
- 反算可用现有 `mapEditedTimeToSource` 路径，需覆盖转场、变速、空隙与全屏文字暂停窗。

## 未覆盖
