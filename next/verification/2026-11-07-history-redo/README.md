# 头部撤销／重做按钮与快捷键复核（alpha.91）

安装版 0.2.0-alpha.91／2026.91.0。复核第 14 轮主轨验收留下的「重做未恢复」悬案：主轨裁剪后分别用头部按钮（AXPress）与快捷键触发撤销／重做，观察配置与按钮可用状态。

## 结果

| 步骤 | 结果 |
| --- | --- |
| 基线 | 头部两个无标题按钮（x1031／x1063, y37）：undo enabled=1、redo enabled=0 |
| 右端裁剪 (1643,701)→(1503,701) + 保存 | `segments[0].end` 8.0→7.264；undo、redo 均 enabled=1 |
| AXPress 头部撤销按钮 | 配置回退 7.264→8.0 |
| AXPress 头部重做按钮 | 恢复 7.264；再次重做无变化、redo enabled=0（符合「没有更多步骤」） |
| 点击时间线获得焦点后 Cmd+Shift+Z（从 8.0 出发） | 恢复 7.264 |
| 随后 Cmd+Z | 未回退（焦点/处理器差异未定位） |

## 结论

- **历史逻辑与头部按钮工作正常**：撤销、重做都能通过 AXPress 精确回退／恢复主轨裁剪；第 14 轮「重做未恢复」不是历史栈故障，当时用鼠标坐标点击头部按钮未真正触发（本轮改为 AXPress 后通过），因此第 14 轮的该条未决项由本轮修正。
- **快捷键行为仍不完全稳定**：点击时间线后 Cmd+Shift+Z 可以恢复一次；紧接着 Cmd+Z 未生效。焦点归属、是否被原生输入框消费、以及是否命中编辑器全局监听尚未定位，不能据此宣称快捷键可用性通过。
- 基线 undo enabled=1（尚无编辑）说明打开工程/迁移可能产生初始历史条目；与第 14 轮观察到的「多余一次空撤销」可能同源，留待后续专项。

## 未覆盖

- 快捷键焦点与处理器路由的原生复现（需要事件日志或组件级键盘夹具）；撤销／重做跨分割、跨多步编辑的完整矩阵；其他轨道的历史按钮一致性。第 14 轮主轨证据的对应条目已由本轮 README 更正说明。
