## 对照与诊断

[Cap 0.6.0固定提交](https://raw.githubusercontent.com/CapSoftware/Cap/6cfdd172cd53b1d6861852288c2192a8ab743687/apps/desktop/src-tauri/src/recording.rs)的点击区间生成函数与当前项目逐字相同，修复后仍相同。预留300毫秒、点击后2500毫秒、间隔2500毫秒合并；因此相邻点击不到约5.3秒可连成一个长自动跟随镜头，不等于只记录第一次操作。只读本机若干单段录制的统计复算与保存跨度一致，未据此宣称所有报告都正常；没有读取画面/音频，原始/逐项用户活动统计不入库。

固定源码HTTPS下载成功，源文件SHA见source-validation.json，离线仅留生成函数片段和来源/AGPL声明。当前main元数据接口返回版本，但raw路径404；不拿浏览器缓存页面当最新主分支代码已验证。

## 真实缺陷与修复

分段cursor_events返回各take的捕获时钟，预览以该take的latest_start_time为可见零点。原generate_zoom_segments_for_project直接extend各段事件，没有减画面起点/加累计片段时间，后段点击会挤到前段，或共享epoch的大时间被全局截止丢掉。

新映射减去与预览相同的媒体起点，丢弃take有效范围外事件，再加前序片段时长；空cursor段仍占时间。点击区间合并、默认缩放量、动画曲线、焦点运动/模糊不动，没有为了制造数量拆连续操作。

原两项完整生成入口/合成cursor文件测试均失败（1对3、1对2），before-valid.log.gz保存有效算法复现。第一次执行因DYLD_LIBRARY_PATH使用相对路径导致运行库未加载，修为本机绝对路径后复跑同一已编译测试；before.log.gz是环境失败，不计算法失败。

修复后5项通过：三take分别落1.7–4.5、9.7–12.5、17.7–20.5；预览媒体起点；无cursor段偏移；捕获边界不串段；旧共享epoch兼容。另加6项原点击规则回归，共11项通过，保留短连续操作合并、长空闲分开、鼠标松开延长、末尾停止点击忽略等语义。数据是临时合成JSON与声明媒体参数，没有开录/访问硬件或修改用户工程。

cargo fmt --all已执行；cap-desktop release check结果另见check.log.gz。本轮没有新增前端API/字段/手改绑定，未动Rust渲染或JS动效；上轮142项界面不因本次纯时间映射重复构建。
