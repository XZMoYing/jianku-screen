# 编辑器与动态壁纸导出验证（alpha.20）

## 原因与设计

首页/演示在 alpha.19 已使用系统实时播放器，但编辑器和独立导出程序仍通过 FFmpeg 逐帧读取视频壁纸，再做 CPU RGBA 转换和上传。对本机 3840×2160、239.76 fps、10-bit SDR HEVC 航拍壁纸，这会把解码、转换、合成和编码串行化。CPU/GPU 总占用没有满，不能据此排除阻塞等待或视频解码引擎限制。

连续播放使用与播放会话绑定的原生播放器，停止会话即释放；会话标识保证旧播放的清理不能停掉新播放。暂停、定位、缩略图与导出使用项目已有的 AVAssetReader，按时间戳取帧，再通过已有 IOSurface GPU 转换器合成。导出并不依赖墙上时钟，也不复用屏幕上正在播放的帧。精确读取只预取一帧，与合成/编码重叠；缩略图有独立图层，避免打断播放器。

任意时间点直接设为 AVAssetReader 的起点，会把第一帧时间戳截到该位置；回拖检查发现后，改为复用已有关键帧索引，从前面的关键帧取样。HDR、透明和非 4:2:0 源继续走原精确回退；这部分性能不在本次优化结论内。没有降低输出分辨率、压缩质量、阴影、缩放、光标或模糊采样；原生壁纸纹理保留源尺寸。

## 受控导出对比

M1、16 GB、macOS 14.7.4。使用本机自制合成工程副本，2 秒、60 fps，分辨率上限 960×600、实际竖向输出 340×600；两份工程只切换背景源，沿用同一画面配置和导出参数。旧版使用 alpha.19 应用内实际附带的导出程序；新版完整构建会同时更新应用与独立导出程序。没有修改用户工程，系统壁纸及其成片不提交到仓库。

首次新通道验证：渐变约 1.21 秒，视频壁纸约 3.22 秒；旧版分别约 1.41 秒、33.78 秒。原始计数见 [旧导出](export-before.json) 与 [精确通道初测](precise-export-after.json)。随后以实际安装包内的程序单独复测 1920×1080，结果见下表。

只替换精确解码仍不足以保证编辑器连续播放：精确读取的顺序吞吐可能低于播放时钟，一旦开始丢帧，追赶又会增加解码量。因此最终编辑器播放切换到播放器调度；不能用精确通道的理论吞吐代替编辑器可见窗口帧率。

## 完整预览与横向导出

另将自制工程设为 16:9，在“完整”预览质量下确认实际绘制尺寸为 1920×1080，保持缩放和 3D 运镜。回调统计来自页面上主预览画布的实际 `putImageData` 调用；WebSocket 帧号只辅助识别重复帧，不拿原生提交次数当显示帧率。测试后恢复了原来的“一半”预览设置，并未通过降低预览质量取得结果。

安装包的 2 秒、60 fps、1920×1080、Maximum 压缩设置对比见 [export-wide.json](export-wide.json)：

| 背景 | alpha.19 | alpha.20 |
| --- | --- | --- |
| 渐变 | 2.15 秒 | 1.90 秒 |
| 实际视频壁纸 | 34.17 秒 | 3.57 秒 |

这是一轮本机短片实测，视频壁纸约快 9.6 倍，不推及所有长工程或素材。另导出含缩放与 3D 运镜的 6 秒工程；[export-validation.json](export-validation.json) 记录 1920×1080、60 fps、360 帧，完整解码无错误。系统壁纸及成片均未提交。

竖向与横向的首轮可见预览计数分别保存在 [portrait-playback.json](portrait-playback.json)、[wide-playback.json](wide-playback.json)。最终横向安装包不抓窗口图像的再次播放约 55.96 fps、P95 32 ms、最大 34 ms；首次播放含图像抓取开销，约 56.27 fps、最大 34 ms，不宣称全程恒定 60 fps。竖向 608×1080 首次播放约 56.6 fps，再次播放约 55.2 fps。

**精确定位仍需优化**：暂停后回到 1.5 秒的位置，最终横向约 2.17 秒才收到该帧；这属于长 GOP 高帧率源的精确读取开销，没有因连续播放恢复流畅就标为解决。

预览区域的像素抽样见 [window-pixels.json](window-pixels.json)：3.09 秒、26 次采样得到 12 种画面，未保存图像。此次只裁取主画布，排除时间线和播放数字；采样跨越播放/暂停阶段，因此该计数只确认画布实际变化，不用于计算帧率。

## 精确性与边界

[sampling-tests.txt](sampling-tests.txt) 覆盖顺序、预取、回拖、循环和重复请求。合成 60 fps 视频的选帧时间戳与原通道一致。RGB 比较有部分帧的平均通道差小于 2/255；原生与 FFmpeg 颜色转换存在舍入/色度处理差异，未宣称视频像素逐字节相同。独立的原生像素平面转换测试仍逐字节相同。真实高帧率壁纸确认返回原始 4K IOSurface，而非 CPU RGBA 回退。
