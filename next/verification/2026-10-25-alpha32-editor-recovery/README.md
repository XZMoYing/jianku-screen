# alpha.32：错误工程的关闭、重试与退出保存

日期：2026-10-25。素材均为独立合成工程；Android、iPad、物理副屏及会议共享按用户要求继续顺延。

## 已修复

- 退出保存监听移到编辑器路由外层，立即注册并独立于内容的加载与错误边界。编辑内容尚未挂载时也能响应退出；已有正常工程仍完整等待名称和配置保存。取消、请求替换与页面销毁后的迟到结果不能确认新的退出请求。
- 错误页“关闭窗口”从浏览器的 `window.close()` 改为原生窗口关闭。新增“返回首页”，只关闭当前错误窗口，其他工程保留；支持重新加载、展开错误详情，小窗口可以滚动。恢复或窗口操作进行中避免重复提交，失败在当前页面提示。
- 初始工程信息查询显示明确错误，不再依赖可能在后台暂停的自动重试。查询或路由早期失败也能进入错误页。素材或工程信息放回原位置后可点击“重新加载”，不改写缺失路径或伪造素材。
- 保存失败的退出提示、工程名称保存错误及新增文案提供中英文。技术错误保留在详情或日志中，未把动态技术异常当成完整翻译。

## 原版对照与修复验证

alpha.31 的普通素材缺失错误页能够正常退出，见 [控制组](baseline.json)。最初尝试拦截只读的 Tauri `invoke` 方法未生效，空监听数组不能证明缺少监听，已在记录中注明。后续故障注入改为拦截自身测试页面的请求传输，不修改产品接口。

两项明确复现见 [原版操作](baseline-actions.json)：错误页点击关闭后窗口仍存在；将有效工程的编辑实例请求暂时挂起后，退出因没有保存确认而等待超时。源码中的监听处于 `onMount`，会被未完成的编辑器 Suspense 推迟；新监听保留在外层路由中。

第一版修订测试时又发现，窗口打开后工程信息失效，25 秒内仍显示加载骨架。最终关闭该本地信息查询的自动重试，以显式错误和重新加载处理；记录见 [中途发现的问题](metadata-first-failure.json)。

8 组打包 debug 的实际控件/退出测试通过，事件及文件核对见 [interaction.json](interaction.json)，脚本见 [review.js](review.js)：

1. 编辑实例请求被挂起时正常退出。
2. 点击错误页原生关闭按钮，编辑器窗口实际消失。
3. 正常与错误工程同时打开，从错误页返回首页，正常工程仍存在，退出时保存其未完成的名称修改。
4. 缺失视频放回原位置后点击重新加载，进入编辑器；录制元数据字节不变，素材哈希与原始合成视频一致。
5. 窗口打开后工程信息变为无效 JSON，显示错误；还原原字节并重新加载后恢复编辑。
6. 早期路径查询失败仍显示错误页并正常退出。
7. 普通素材缺失错误页正常退出的控制组。
8. 注入名称写入失败，退出被阻止且原名称未改变；解除注入后重试，修改保存成功才退出。它不是物理只读磁盘或磁盘写满的验收。

错误页实际截图见 [debug-error-screen.png](debug-error-screen.png)。8 项保存桥接测试、8 项名称保存、15 项配置保存、3 项准备播放交接共 34 项前端测试通过；桌面类型、相关 Biome、Rust 格式和 `cap-desktop` 编译检查通过。

额外进行 3 轮暂停、回到开头与重播冒烟检查，见 [playback-smoke.json](playback-smoke.json)。原观察器只挂钩主线程 Canvas2D，第一次没有捕获绘制，但原生仍持续渲染和发送；失败记录保留在 [playback-observer-first.json](playback-observer-first.json)。随后改用应用已有绘制计数结合帧元数据复测通过，实际模式记录为 `canvas2d`。首次未捕获的原因没有完全分类，不把后一次通过当作全部偶发播放问题已解决。此观察方式检查绘制进度，不保证每条记录就是对应像素帧，也不是稳定显示帧率基准；产品渲染代码未因此改变。

## 范围与交付

此阶段处理加载与错误界面的退出/重试，不承诺自动找回移动的素材，也不把缺失素材放回后的重试视为损坏视频修复完成。恢复过程被中断、运行中异常后的未落盘编辑、崩溃/断电恢复、快速重载与退出交叠、真实磁盘权限/空间异常仍需继续验证。初始加载骨架中的部分历史英文标签也保留在本地化待办中。
