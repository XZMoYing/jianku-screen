## 实际界面与文件检查

旧 alpha.37 对照中，将自己的测试配置改为 0444 后，通过实际留白控件递增 14→14.1，旧版仍替换文件且把权限变回 0644。见 `old-readonly-baseline.json`。测试只操作独立合成副本，随后正常退出并复原副本。

新安装 alpha.38 的同一操作完成五项检查，原始结果见 `interaction.json`、`review-final.log` 与 AX 采样：

1. 只读配置下改留白，内存显示 14.1，旧文件逐字节保持，磁盘留白仍为 14；实际显示中文自动保存失败提示。
2. 等待 9.2 秒，提示仍然可见；固定标识未造成堆叠。见 `save-failure.png` 与 `ui-toast-persisted.json.gz`。
3. 正常请求退出，保持只读至少 7 秒（超过退出保存确认的 5 秒等待）；应用保持运行、旧字节不变，原生日志明确记录配置只读导致 Quit canceled。它不是强制杀进程的测试。
4. 恢复原权限后，实际发送保存快捷键，磁盘写入最新 14.1，错误提示清除，本次临时文件为零；见 `save-retry.png`、`ui-save-retried.json.gz`。
5. 再次正常退出成功。之后从统一安装路径打开归档中的独立示例，实际窗口与运行路径/进程核对见 `delivery.json`、`final-ax.json.gz` 与 `release-editor.png`。

检查运行两轮：第一轮等待退出决定 2 秒，第二轮延长到 7 秒；均观察到原生日志取消退出与随后成功保存。`interaction-first.json` 保留第一轮结果。没有往生产包注入脚本或新增产品调试接口，使用当前已授权的系统 Accessibility API 读当前应用窗口、操作已确认的控件。辅助控制器仅遍历本产品窗口；`ax-control.swift` / `review.py` 是本机一次性检查记录，硬编码本轮独立临时工程，不能改指向用户工程后运行。

安装前第一次回滚校验写错相对路径而中止，安装未改；提前运行的界面检查也因仍是 alpha.37 而拒绝。该中途记录保存在 `review-before-install.json.gz`，不计入产品失败或通过数量。修正路径、完成安装后才运行上面的正式检查。
