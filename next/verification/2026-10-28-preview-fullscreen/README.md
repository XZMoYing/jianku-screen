## 实现与实测

全屏沿用同一个Player/PreviewCanvas与渲染流，隐藏并停用编辑栏/轨道交互，保留播放、暂停、首尾定位、进度条和质量菜单。新增系统窗口权限只授予editor-*。不降低画质、动态模糊或任何画面效果，不增加媒体窗口。控制器串行处理快速进入/取消、关闭、失败重试和外部退出。

alpha.43真实鼠标操作：普通窗口播放→进入全屏→Escape返回→暂停，播放按钮在三个阶段保持播放中，实际帧元数据304条、帧号0→318不倒退；操作与原记录见 `alpha43-live-pointer-actions.json` 和 `alpha43-live-pointer-frames.json`。这不是实际显示持续60fps或物理音频同步证明。

暂停时全屏进度条定位4秒，严格等待收到240帧，见 `alpha43-progress-seek-frame.json`。全屏真实菜单720p→144p→720p分别输出256×144、1280×720。0帧在进入前、全屏中和返回后RGBA载荷SHA完全相同；退出恢复1275×800、位置(202,102)，工程配置SHA未变。见 `alpha43-final-acceptance.json` 及对应帧头；未保存画面载荷，仅留自制彩条截图。

已有系统全屏时，点击进入/退出预览保持原有系统全屏，外部退出系统全屏后编辑器控件恢复；见 `alpha43-native-ownership.json`。**但该状态下两种自动Escape输入未使预览退出**：有焦点/输入递送的不确定性，尚不能认定产品错误，也不能算通过。按钮退出已验证，普通窗口进入的Escape已验证。原始状态及结果 `alpha43-preview-preserves-native-fullscreen.json.gz`、`alpha43-focused-native-escape.json` 保留，U05b继续调查，不关闭总项。

## 两处初始观察的更正

alpha.42首包0帧曾被误判为暂停定位失败。观察器会先收到缓存帧，该读数不充分。改成等待指定目标帧后，alpha.42也收到240帧，见 `alpha42-strict-paused-seek-frame.json`；不把初次首包当作旧版确定失败。alpha.43在EditorStateChanged确认后重新排暂停渲染，作为取消竞态的时序加固；原生seek只emit状态、preview renderer不发该事件，未形成预览→确认循环。用户此前偶发回零卡住的问题未在这里证明百分百复现/修复。

首轮播放测试使用AXPress、缺少播放成功前置断言，收到的只是244缓存帧，未完成验收。后来从已确认零帧起用真实鼠标播放，逐阶段读取状态及连续帧，才取得上述304帧证据。首轮原始 `alpha43-live-fullscreen-frames.json` 保留为未通过观察，不与正式结果混用。
