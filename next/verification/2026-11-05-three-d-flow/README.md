# 相邻3D镜头连续衔接：源码与实际导出

## 原问题

当前自动3段场景的4/8秒边界原入/出均0，第一处tiltY跳44.04°、rotateX跳-40°、FOV跳15°，第二处tiltX跳-34.19°等。每段内部平滑，但整组依旧硬切，且曝光历史只支持数学相同的拆分轨迹，不能把段内曲线通过当整组观看舒适。

## 实现

加入可保存的joinDuration：缺省0.75秒，显式null直接切换。相邻镜头边界两侧用原有共享缩放弹簧节奏衔接，保留两侧运动的端点切线，角度取短路径；空隙、禁用和重叠不误混。过渡实际宽度受相邻片段长度限制，避免短片段的衔接相互覆盖。运动模糊从同一个衔接后轨迹取样并跨有效边界保留曝光，明确切镜仍保留原边界。

景深参数同步渐变；模式不同则先平滑收旧模式再引入新模式，避免在强模糊下直接换算法。全局模糊强度／既有单镜头曲线／阴影参数不改，不通过关闭效果换流畅。真正分割同一镜头时右半段不额外加一次衔接，保留原轨迹及原入/出边界。

镜头属性提供“与前一镜头衔接”“平滑衔接／直接切换”和时长。没有前一相邻镜头时说明接上后生效；由相邻衔接接管的独立入/出滑块不可误调，独立镜头仍保留旧效果。临时切到直接切换再切回来时记住本面板的自定义时长，收起行在离场动画中不闪回默认数值。相关起止姿态和数量提示本土化，中英文本同步。

## 证据与限制

三个定向原生用例加既有相关用例共25通过，覆盖边界、曝光与明确硬切；既有97个3D前端模型／共享弹簧用例通过，类型与前端构建通过，三个触及原生crate check与fmt通过。默认值从初稿0.45改为0.75后只做必要cap-project check，渲染算法和自定义0.45测试未变。绑定通过现有Rust导出入口生成，diff仅增加一个可选属性；没有手改生成文件。

实际新CLI对自制12秒仪表板分别导出直接切换、0.45秒和0.75秒，完整解码1080帧。主代理查看[同一衔接的连续取帧](join-comparison.png)：上／中／下分别为直接、0.45、0.75，约3.6–4.6秒，每格0.2秒。0.75保留更从容的姿态迁移，作为当前默认；取帧不能代替用户对全速观看的最终判断。未减少输出质量／模糊，来源为项目自有预览资产，不含用户桌面录像。实际MP4／工程留本地，CLI二进制与源文件指纹已记录。
