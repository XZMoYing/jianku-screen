# U19d：摄像头独立投影阴影组件

安装应用仍是alpha.45。本目录验证的是未打包的新渲染组件，源码/CLI指纹见source-manifest.json；U19d父项、成片稳定性和46完整包尚未完成。

## 实现与像素依据

摄像头浮窗和带留白的CameraOnly分别保留自己的实际Composite参数及阴影轮廓；通过原贴图、裁剪/镜像/圆角/模糊/调色处理生成无旧平面阴影的前景与蒙版。摄像头前景P只投影一次，两个caster各自扩散/高斯后依次用D×(1−S)+P×S恢复前景，使阴影位于屏幕之上、所有摄像头前景之下。原统一内容组的13次曝光采样、后续焦外与平面标注保持，不把画面拆成独立时间平均。纹理/pipeline按需复用，关闭阴影/没有摄像头时跳过额外通道。

无留白CameraOnly原本没有外阴影，本组件不额外添加。原型曾把两个摄像头合并作为caster，导致无阴影特写淡入时扩大另一层投影；正确过渡时刻的真实GPU回归显示12240个白背景像素被改动。分开caster后严格0变化，原型未交付。CameraOnly入场发生在start−transitionIn到start，初次测试采样误在稳定段的记录保留。另一个测试同时修改全局背景阴影造成255→254，已固定背景参数、保留逐字节断言；没有放宽门限。大数组失败日志改用有限差异诊断，借用/Arc迭代器的编译错误记录也保留。

局部基线6通过；最终完整cap-rendering库354通过/6原有忽略，cargo fmt/check及严格Clippy通过，最终CLI构建成功。7项专项包含真实GPU：不透明摄像头前景逐像素保持、阴影可落在底层屏幕、透明底alpha正确、带独立留白特写、无留白前后完全相同、隐藏跳过通道、混合转场背景保持及预览/导出相同。红/蓝强阴影图使用压力参数75/70/40，不是新录制默认外观；物理摄像头/设备未验。

## 十组完整成片及未关闭的差异

自制testsrc2摄像头256×256、屏幕4K彩条、已有多段/音频素材构成10个带标记APFS克隆工程。前后各组1280×720/60fps/540帧。PIP运动、场景转场、带留白特写、MacBook摄像头和带留白混合转场按预期变化；无留白CameraOnly、普通二维、隐藏摄像头和仅虚化四组2160帧完全相同。十组PCM完全相同。

关闭阴影一组**首次失败**：第243至539帧共297帧不同，首差帧90174像素变化、最大52；初次严格比较未通过。compare-all-preserving-gates.py继续收集全部用例后仍以失败退出，comparison-violations.json没有豁免。首次异常视频与帧哈希/图像保留。

同一旧45二进制重复导出与旧基线540帧全同；同一新二进制重复也与旧基线540帧全同。ProRes（yuva444p12le）前后540帧全同，只用于视频诊断，MOV路径本来不带音频，首次检查误假定有音轨的错误保留；MP4音频另有十组PCM依据。重复成功**不能证明首次异常已修复**，尚不能归因编码、NV12零拷贝或渲染。需要继续逐帧原始输入/硬件输出及运行间稳定性检查，不能关闭U19d整体、生成已验收46包或据此宣布视觉完全不变。
