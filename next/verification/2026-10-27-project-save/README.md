# 工程配置安全保存与失败提示

日期：2026-10-27。此检查点完成实现与组件回归；当前安装包仍为 alpha.37，打包后的持续提示、重试和关闭交互在下一项 U03 验证，不宣称本轮已经发布新包。

## 修改

`ProjectConfiguration::write` 继续先验证、序列化，再在工程同目录写临时文件并同步，成功后原子替换配置。改用已有 tempfile 依赖持有临时文件，写入或同步返回错误时自动清理；替换失败也清理本次临时文件。原配置是目录/符号链接/只读文件时明确拒绝，普通现有文件的基本权限保留。首次写入失败不产生半份目标配置，下一次可正常重试。

实现沿用项目元数据写入已经采用的成熟路径。Windows 使用与元数据写入相同的开放读取者重命名回退，但本轮只在 macOS 运行，Windows 行为仍需目标环境验证。没有新增依赖、改工程格式或修改用户素材。

桌面保存命令把文件同步与写入放到阻塞任务池并等待结果，避免在异步运行线程执行文件同步。原有预览内存更新保留；写入失败时编辑状态仍在窗口，命令返回失败，不把未保存状态当成保存成功。

自动保存失败现在显示本地化持续提示：检查磁盘空间/权限，并从“工程”菜单重试；固定提示标识避免堆叠，成功保存后清除。手动保存、关闭窗口、导出/导出预览和可携带副本继续等待相同保存边界。现有自动保存调度保持串行、250 ms 合并与最新快照，失败不会无限重试或将旧快照标为已保存。

## 验证

- 工程模块 **159 项**测试通过，包括本轮 **6 项文件写入检查**：部分/完整写入后注入失败，首次保存失败及重试，替换时出现目录造成失败，只读配置，原目标目录，符号链接与基本权限保留。测试使用自己的临时目录，旧配置逐字节比较，失败临时文件/目录枚举也参与断言。
- 保存调度、关闭/标题确认、名称、可携带副本及多语言 **39 项前端测试**通过：失败传播给等待者、保留旧值并重试最新快照、导出不越过失败保存边界等已有回归保持。
- 桌面 TypeScript、`cap-desktop` release 编译检查、Rust 格式、作用域 Biome 与 `cap-project --lib --tests --no-deps -D warnings` Clippy 通过。命令、数量与原始输出见 `checks.json` 及各日志。
- 调用链复核：`context.ts` → `createProjectConfigSave.flush` → Tauri `set_project_config` → 原子写入；`ProjectMenu` 的保存/打开/副本、`Editor` 的退出保存桥与 `ExportPage` 的预览/导出均等待 flush。关闭桥失败会返回错误确认，已有取消、替换请求及迟到确认测试保持。

注入写入/同步错误不等于把实际磁盘写满；正常错误回收不等于进程被强制结束后仍能运行析构。突然断电、强制终止留下的临时文件、尚未发起保存的编辑、复杂文件系统 ACL/扩展属性和 Windows 运行仍不在本次证明范围。两项既有硬件解码色度严格失败未被豁免，正式发布审计继续按交接台账进行。
