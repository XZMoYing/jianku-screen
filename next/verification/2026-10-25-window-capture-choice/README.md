# alpha.27：窗口录制范围选择

日期：2026-10-25。用户确认需要保留遮挡窗口入镜的能力，增加选择权；默认不改变原来的区域录制方式。

## 本轮实现

- macOS 窗口选择列表中增加“过滤其他窗口”开关；选择窗口的录制浮层齿轮菜单提供相同选项。默认关闭，保存后重开沿用。
- 关闭时继续采集该段开始时确定的显示器区域，保留未被既有排除规则隐藏的遮挡内容。开启时使用独立窗口过滤，不重复应用显示器坐标的裁切。
- 电脑 Studio 和即时录制构建器读取同一设置；暂停恢复保留选择，系统重建流复用同一过滤器逻辑，独立窗口重建不再要求原显示器仍然存在。不将这些代码路径全部表述为已实机通过。
- 独立窗口模式读取采集帧的 `screenRect`、`contentRect` 和 `scaleFactor`，映射录制光标到真实画面范围，适应窗口移动及改变比例产生的留边。光标动画、点击、缩放、动态模糊与后期渲染算法保持原实现。

系统 API 依据：[Apple 独立窗口过滤器](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/init(desktopindependentwindow:))、[采集帧内容范围](https://developer.apple.com/documentation/screencapturekit/scstreamframeinfo/contentrect)。本机 Xcode SDK 头文件进一步核对了坐标单位及 API 版本要求。

## 实际验证

`fixture.swift` 创建绿色目标窗口、白色定位点、红色遮挡窗口和合成底板。`review.js` 使用现有 debug 检查入口点击真实开关，确认设置保存，分别录制开关关闭和开启两种情况。测试时关闭麦克风、摄像头和系统音频，完成后还原设置及输入选择。

实际完成两次 Studio 录制，并核对开启模式下的移动、改变比例、暂停与恢复。`verify_capture.py` 根据书签记录的源片段时间逐段解码。静止画面采用时间点之前最近一帧，光标同样取之前最近一次采样，避免 FFmpeg 跳到后续更新帧导致错误结论。

- 关闭开关并遮挡时，抽样画面红色比例为 100%。
- 开启开关并遮挡时，抽样画面红色比例为 0%，目标绿色画面仍完整存在。
- 9 个视频对照点通过；具有白色定位点的 8 个对照点，光标与目标点的抽样误差为 0.69–2 像素，验收阈值 5 像素。像素网格采样步长为 4 像素，该数值包含网格取样误差，不代表每帧亚像素级精度验证。
- 改变窗口比例时，视频保持该源片段的输出尺寸并产生留边，光标按实际内容范围定位；暂停恢复后的新源片段使用新窗口尺寸。
- 3 项采集坐标原生测试、1 项设置序列化原生测试、13 项相关前端测试和 1 项原生类型导出测试通过。`cap-recording`、`cap-desktop` 的 Rust 检查、格式检查及桌面 TypeScript 检查通过。生成的绑定随原生改动提交，没有手改生成文件。

数值见 [observations.json](observations.json)。未提交完整录像、完整桌面截图或用户应用数据。debug 打包及统一路径安装已通过；优化版交付结果以 `delivery.json` 为准。

## 剩余范围

以下仍需验证：物理跨显示器及显示器断开、窗口最小化或关闭、同应用独立对话框/菜单/子窗口、系统强制中断后的采集重建、音频/摄像头组合、即时模式实际录制及长时间录制。macOS 13.1 以下没有本轮使用的窗口屏幕位置帧信息，新光标映射未完成旧系统验收。

关闭开关沿用原有区域行为，该区域不会在同一源片段内动态跟随窗口移动。这与开启独立窗口采集时的行为不同，不能把默认模式描述为已实现窗口追踪。

Android 静止尾段、动态壁纸性能、复杂工程播放、书签扩展及其他功能不属于本轮完成范围，统一维护在 [待验证项目交接](../../../docs/待验证项目交接.md)。
