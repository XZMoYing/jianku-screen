# alpha.30：内边距与内框

2026-10-25。本阶段按用户要求继续实现剩余功能，Android、iPad、物理副屏和会议共享验收顺延。测试只使用自制图案、合成视频和独立测试工程。

## 行为定义

- 留白控制画面外侧与背景之间的空间；内边距控制视频与装饰外框之间的空间。无装饰外框时也可使用内框。视频等比缩小，输出画幅保持不变，不靠拉伸视频或裁掉内容腾出空间。
- 内边距范围为 0–100 参考像素，以视频短边 1080 像素为基准，随视频尺寸、缩放与运镜同比例变化。内框可自定义颜色与不透明度；未指定样式时使用黑色、50% 不透明度。内边距默认为 0。
- 首页录前设置、编辑器、截图编辑与演示控制复用同一控件；同一项目配置进入既有 GPU 合成器，预览、导出和实时输出共用布局。沿用原有圆角、阴影、细边框、动态模糊与 3D 合成路径，不更换动画曲线，也不通过降低效果质量实现。
- 新增 `background.insetStyle` 可选字段。旧工程缺少该字段时仍可读取，原有留白与内边距值保留；旧工程若保存了非零 `inset`，该数值现在会真正生效。设为 0 时不绘制内框。
- 截图中的标注跟随内容矩形缩放和平移；撤销/重做同时还原设置与标注，等待恢复操作之后的新渲染版本，避免旧画幅重复变换已恢复的标注。截图裁剪框也读取包含内边距、外框和画面位置的布局。
- 顺带修复截图工具原有固定画幅的几何差异：原生在判断适配方向时使用单精度裁切比例，前端现在按同样精度判断，避免恰好匹配画幅时落入另一分支。渲染器原有零内边距布局没有因此改写。
- 修复键盘滑块的手势收尾：原有依赖未在 Home/End 跳转时发出结束通知，现在失焦或按撤销键也会结束手势；正常拖动仍在松开时收尾。截图历史按结束时的实际快照差异记账，避免依赖响应式观察回调的先后顺序。截图工程文件夹和目录内原图使用相同的保存目录定位，保存错误返回调用方。
- 新建浏览器外框的默认地址文字改为 `jianku.local`；这是装饰文字，不访问服务器。用户已有自定义地址保持。

[参考产品的背景说明](https://screen.studio/guide/background)用于确认 Inset 的功能含义；该页没有公开完整单位、默认数值与实现。这里的参考像素定义为本产品的明确约定，不作为参考产品像素完全一致的证据。

## 彩色测试片段的缩放顿挫

用户确认顿挫出现在彩色测试片段。检查器实际使用 Canvas2D 直接显示：WebSocket 帧先进入等待下一次动画回调的槽位，行跨度转换异步完成后直接绘制。原先槽位仅保留一个待显示帧，到帧短暂聚集时会覆盖尚未绘制的上一帧。每次绘制本身约毫秒级，不能只靠资源占用判断这条显示路径是否顺畅。

编辑器现在使用最多 3 帧的顺序队列，每次显示刷新取出最早一帧；队列超限时丢弃最旧帧，避免无限延迟。跳转、暂停/播放、帧序/时间不连续及尺寸/格式改变时失效旧队列；异步行跨度转换带代次，过期结果不回写。RGBA、NV12 的 WebGPU 与 Canvas2D 直接显示均进入同一调度规则。首页、演示与准备阶段的其他消费者继续使用默认最新帧策略。未降低视觉质量，未替换媒体动画曲线。

实际打包调试包使用自制静止网格、1–4 秒的 1.5 倍自动缩放，记录 5 秒 WebSocket 收帧与 Canvas2D 绘制调用。原版静置测试收到 295 帧、绘制 283 帧，内部收到但未显示帧有 10 个，缩放区间内有 6 个。候选版收到 297、绘制 294，内部缺帧只剩开播第 9 帧，缩放区间内没有。包含最终暂停/跳转失效处理的复测收到 294、绘制 292，缩放区间也没有收到未绘制帧；采样结束附近一次原生帧序跳跃时丢弃旧队列，未显示第 293 帧。停止采样时仍可能存在传输中或排队帧，因此收帧与绘制总量之差不全等于中途丢帧。

暂停后在时间尺拖到开头并再次播放连续验证两轮，回到开头按钮再验证一轮；分别绘制 83、82、82 帧，从第 0 帧推进到 82、81、81，首帧调用延迟约 19、31、25 毫秒。相关传输集成测试新增连续突发、有界队列、NV12、前后跳转、暂停编辑、复位清理及过期转换等覆盖。

另用四段彩色素材补测连续播放及重播：按钮回到开头后再用时间尺定位两轮、仅按钮一轮均通过，单独时间尺回退的诊断复测也从第 0 帧持续推进。但第一次追加测试在 1.4 秒观察窗内的重播断言失败，未保存该轮逐帧细节；随后成功不能证明这个偶发情况已解决。已将复杂工程回退的重复验收继续保留（V2-Playback-Resume-01），不归因于未经证实的视口或性能问题。完整成功及失败记录见 [彩色片段补测](color-playback.json)。

这些是调试包中的短时绘制调用与传输记录，发布构建同时编译，既不是优化版帧率基准，也不能测量物理显示器真正呈现时间；原生生产端未发送的帧不包含在“收到未绘制”指标。未据此宣称所有缩放抖动或卡顿完全消失。原始记录与边界见 [preview-pacing.json](preview-pacing.json)、[修复前](playback-before.json)、[候选版](playback-after.json)、[最终调试包](playback-final.json)。
