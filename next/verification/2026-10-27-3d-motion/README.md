# 3D 透视运动模糊：U18a 组件检查

日期：2026-10-27。当前安装版本仍为 alpha.38，本目录记录尚未单独打包的渲染组件。U18 的速度曲线及整体观感没有完成，不能把本项作为“3D 已经全部调好”的验收。

## 发现与实现

现有 3D 模板、新镜头和场景生成明确写入线性关键帧，且默认切入/切出时间为零；其 blur 参数控制固定空间焦外。普通缩放则使用 `zoom_spring.rs` 的解析弹簧时间线和运动模糊。这是两项具体差异，不等于已证明全部主观观感来源。

本项先补齐透视运动采样。每帧取当前镜头内、过去曝光窗口的 13 份完整逆透视变换，包含旋转、平移、FOV、距离及 3D 下的整卡缩放，以抛物权重合成。曝光采用普通缩放同一 60 fps 基准和全局强度，按实际运动而非导出帧间隔确定；只把当前内容纹理沿相机轨迹采样，不重复解码过去的媒体内容。固定焦外和背景继续走原路径。

位移低于已有一像素激活界限、静止或关闭模糊时保留单采样清晰路径；极端投影运动沿用公共位移上限。曝光不跨镜头取姿态，瞬时缩放切点不增加拖影；退回平面时的曝光尾部保持整卡坐标。普通缩放时间线、光标曲线、源分辨率与导出压缩参数没有改变。已排序的关键帧直接借用，避免每个时间样本重复分配排序。

## 验证范围

`cap-rendering` 库 336 项通过、0 失败、6 项原有忽略（两个基准、图片导出、三个无头 GPU 检查；本项另外使用实际导出运行 GPU），其中 17 项 3D 数学检查通过，包括新增的静止/禁用/边界、整卡缩放与半曝光、极端速度有限值和上限检查。格式、scoped release 编译与库 Clippy `-D warnings` 通过；初次严格 Clippy 揭示 `live.rs` 中三个已有的 `f32 as f32`，已移除同类型转换，未改变弹簧数值。保留初次失败及最终成功输出，不通过压制警告获得通过。

实际 GPU 导出使用 alpha.38 包内 `cap-cli` 为对照、新源码 CLI 为候选，同一独立合成工程各 9 秒、1280×720/60 fps、最高质量。包含动态背景、变速/重排、双配乐、内框与浏览器框。五种基础情况外，再覆盖固定焦外与新增运动模糊的组合；最终源码重新构建并重跑全部 14 次导出，七组全部通过；普通缩放、静态 3D、关闭模糊和静态焦外共 2160 帧逐字节相同，移动/叠加缩放/叠加焦外分别有 139/181/70 个解码帧变化，七组 PCM 均一致。`export-comparison.json` 是最终结果真源，逐项记录全部解码帧、媒体参数与 PCM。数学测试不能代替着色器运行，实际导出同时验证了 GPU 管线。

`motion-frame74.png` 左侧为原版、右侧为新增运动采样，取相同的第 74 帧；仅用于观察方向与边缘，不作为整体舒适度结论。有损视频编码会把变化传播到之后的预测帧，变化帧数不能当作启用模糊的原始渲染帧数。没有放宽静态路径的逐字节对照要求。

导出日志中的耗时是本机短合成片观察，混有冷启动、编码与检查负载，不能据此宣称全部工程性能提升或实际预览达到某帧率。GUI、整体速度曲线、更多帧率/比例/镜头组合和用户观感留在 U18b/U18c；两项既有严格色度差异及播放时序问题也没有因此关闭。

## 重跑与输入

`inputs/` 保存最终复跑实际使用的七组配置及元数据；`inputs-manifest.json` 保存当次合成输入和两个 CLI 的指纹。媒体未重复提交：复用本机独立的 `/private/tmp/jianku-alpha38-save/导出一致性示例.jks`，不包含用户录制内容；`make-fixtures.py` 需要该九秒基底的副本，不生成或下载替代素材。

在 `next/cap/` 中，先将目标平台原生库路径设为运行环境，再按以下顺序使用新目录：

```sh
python3 ../verification/2026-10-27-3d-motion/make-fixtures.py \
  --base-project '/private/tmp/jianku-alpha38-save/导出一致性示例.jks' \
  --directory /private/tmp/jianku-3d-rerun
DYLD_LIBRARY_PATH="$PWD/target/native-deps/lib:$PWD/target/native-deps/onnxruntime/lib" \
python3 ../verification/2026-10-27-3d-motion/run-exports.py /private/tmp/jianku-3d-rerun \
  --before-cli '/Applications/Jianku Screen Next.app/Contents/MacOS/cap-cli' \
  --after-cli "$PWD/target/release/cap"
python3 ../verification/2026-10-27-3d-motion/analyze-exports.py /private/tmp/jianku-3d-rerun
```

基线必须确认为 alpha.38；后续安装新包后应改用保留的 alpha.38 归档路径，不把新安装版误作原版。生成器和导出执行器遇到已有目标拒绝覆盖。没有基底素材时，清单仍可检查已保存证据，但不能声称已复现原始成片；需另外构造输入并明确区分。
