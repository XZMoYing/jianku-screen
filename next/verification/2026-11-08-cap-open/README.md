# 旧 .cap 工程打开与重复打开验收（alpha.92，U24 剩余）

安装版 0.2.0-alpha.92／2026.92.0。把自有合成工程复制为 `.cap` 后缀（改 pretty_name 为「旧cap验收」），核对冷启动显式打开、运行中重复打开与 Finder 默认处理器行为。

## 结果

| 用例 | 操作 | 结果 |
| --- | --- | --- |
| 冷启动显式打开 | 应用未运行 → `open -a 应用 旧cap验收.cap` | 通过：编辑器打开，工程名「旧cap验收」，1 个编辑器窗口 |
| 运行中重复打开同一文件 | 再次 `open -a 应用` 同一 .cap | 无副作用：仍 1 个编辑器窗口、工程名不变，工程配置 SHA-256 未变（`a403b9a5…98981`） |
| Finder 默认处理器 | 应用未运行 → `open 旧cap验收.cap`（不带 -a） | **未启动本应用**（无进程），说明 `.cap` 未注册为默认打开方式；当前安装只把内容类型处理器注册给 `.jks` |
| 工程配置完整性 | 显式打开/重复打开阶段 | 哈希与打开前一致（\`a403b9a5…98981\`）；**正常退出时应用重写配置**：相对源工程仅移除 \`background.insetStyle=null\` 与 \`timeline.segments[0].id="speech"\` 两处（序列化归一化），其余 0 差异 |

## 结论与边界

- 旧 `.cap` 工程可以通过显式 `open -a` 打开；同一文件重复打开不会产生第二个编辑器窗口，也不会改写工程配置。
- Finder 双击 `.cap` 不会打开本应用（未注册该扩展的默认处理器）。是否为 `.cap` 注册默认打开方式属于产品/兼容决策，可能与上游 Cap 应用冲突，本轮只记录现象，不擅自修改文件关联。
- 未覆盖：Finder 拖到 Dock、命令行 `--args`、失败路径（不存在/损坏 .cap）、应用内「打开工程」选择器的 .cap 过滤与打开。
